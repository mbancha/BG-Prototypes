# Instructions for digital prototype work

Read [CLAUDE.md](CLAUDE.md) for repository architecture and workflows, then the
[prototyping playbook](.claude/skills/board-game-prototype/SKILL.md).
These instructions apply to human developers and all coding assistants.

[Player experience standards](docs/PLAYER_EXPERIENCE.md) are required for new
prototypes and changed UI flows. Component-shaped graphics, direct interaction,
automatic turn flow and readable cards are baseline playability, not optional
polish. Include the acceptance evidence in each game's verification notes.

Read the game's ARCHITECTURE.md and DECISIONS.md before changing it. Keep games
standalone. Preserve private information. Do not migrate unrelated games or
change print outputs without explicit scope. A documentation update does not
certify existing games or the starter template as meeting the new standard.
